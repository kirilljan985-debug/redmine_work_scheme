# План проекта Redmine Work Scheme

Живой план: текущее состояние и свободные треки. Выполненные задачи
с результатами и проверками — в `PLAN_HISTORY.md`; точка продолжения —
в конце `AGENTS.md` (читается в каждой новой сессии).

## Правило сопровождения изменений

Любое изменение проекта выполняется вместе с актуализацией плана и файла
памяти `AGENTS.md`: до работы фиксируется задача и критерии готовности,
после работы — фактический результат, тесты, коммит, push и состояние CI.
Если изменение не требует отдельного пункта плана, в плане всё равно
записывается краткая отметка о нём.

## Проверка перед завершением задачи

1. Обновить `PLAN.md` и `AGENTS.md`.
2. Выполнить релевантные локальные проверки и тесты.
3. Проверить `git diff` и `git status`.
4. Создать коммит и отправить его в GitHub.
5. Дождаться зелёного CI или зафиксировать диагностику падения в памяти проекта.

## Текущая работа — раунд фиксов по четвёртому ревью (2026-10-27)

Проведено четвёртое объективное ревью коммита `e9d8390` (v0.5.0): 4
суб-агента по непересекающимся областям, каждая находка с доказательством
по коду. Итог: **P0 = 0, P1 = 3, P2 = 8, P3 ≈ 27** (после дедупликации).

Критерии готовности раунда фиксов: P1 и P2 исправлены все, P3 — выборочно;
юнит/интеграционные тесты на валидаторные правки; локальные `ruby -c`,
`node --check`, dev-проверки в браузере; коммит + push + зелёный CI на всех
4 джобах; план и память обновлены. Код ещё не правился.

### P1
1. `work_scheme_editor.js:110-137` — `restoreSnapshot()` не вызывает
   `redraw()`: после undo/redo нет hit-путей, стрелки невыбираемы кликом.
   Фикс: `this.redraw()` в конце restoreSnapshot (после сброса sel).
2. `work_scheme_editor.js:499` — id сценария = `'scenario'+length`: после
   «удалил → добавил» дубликат id, save навсегда 422
   (`ws_error_scenario_dup_id`), в UI id не виден. Фикс: счётчик по
   максимуму существующих `scenario(\d+)`, как `maxNodeSeq` у узлов.
3. CI — рантайм-JS не покрыт автоматикой (только `node --check`);
   регресс рендера/проигрывания уходит в main зелёным. Фикс: jsdom-smoke
   (init на dev/scheme.json, наличие .ws-canvas) либо хотя бы абзац об
   ограничении в README.

### P2
4. `work_scheme.js:891` — `markEdgeComplete` не очищает inline
   `strokeDasharray` → пунктирная стрелка становится сплошной до сброса
   (маскируется тем, что дефолтная пунктирная связь — возвратная).
   Фикс: `pathEl.style.strokeDasharray = ''`.
5. `work_scheme.js:1082` + `scheme.rb:166-169` — `w`/`h = 0` проходят
   валидатор, `getTotalLength()=0` → NaN в `sampleAt` → TypeError в rAF,
   проигрывание ступорит с заблокированной кнопкой. Фикс: кламп w/h ≥ 1
   (или минимум 20) в валидаторе + guard `total <= 0` в `animateMarker`.
6. `work_scheme_editor.js:110-137` — undo не сбрасывает
   `activeScenarioId`/класс `ws-scenario-capture` → после Ctrl+Z drag
   узлов мёртв без видимой причины. Фикс: сброс в restoreSnapshot.
7. `work_scheme_editor.js:458-462, 757, 916, 928, 956-961` —
   `markFormDirty` на каждом `input`-тике range/color затапливает
   undo-историю (Ctrl+Z отматывает по пикселю). Фикс: мутация по `input`
   без записи истории, один снимок по `change` (как у resize-жеста).
8. `work_scheme.js:709-726` — drag узла считает delta в клиентских
   пикселях, применяет как SVG-юниты: отставание от курсора и прыжок при
   масштабе ≠ 1. Фикс: конвертация через `getScreenCTM().inverse()`
   (как `svgPoint` в редакторе).
9. `work_scheme_editor.js:882-889` — селекты «Откуда/Куда» допускают
   `from === to`: самострелка проходит валидатор, рендер деградирует.
   Фикс: запрет равенства в `onchg` селектов.
10. `app/views/work_scheme/_block.html.erb:41` — контейнер без
    `data-layout="modern"`: dev-превью атрибут ставит, production — нет;
    CSS-правила modern потомковые, на странице схемы и dashboard-блоке не
    применяются никогда. Фикс: добавить атрибут в партиал + ассерт в
    pages-тест.
11. `README.md:168-169` — инструкция query_id учит читать id задачи из
    `/issues/123`; сохранённый запрос открывается как
    `/issues?query_id=123`. Фикс: переформулировать на `query_id=`.

### P3 (выборочно, по группам)
- Валидатор: кламп `w`/`h` снизу (дополняет №5); regex
  `\A[A-Za-z0-9_-]+\z` для id сценария (как у узлов); `dashed: "true"`
  строкой молча → false (явная ошибка или приём строки); лимит размера
  save (~60 КБ) для MySQL TEXT — перед внедрением сверить БД живой машины.
- Редактор: очистка числового поля обнуляет координату (`num('')===0`) и
  нет min-клампа w/h в полях; палитра стрелок создаёт дубли пары молча;
  bend-слайдер max=100 при валидаторе 0–200; сброс конца стрелки на её
  текущую цель стирает `toSide` и даёт холостую запись истории;
  `pendingFrom` не отменяется кликом по пустому месту и Escape; undo
  названия схемы не обновляет `#ws-editor-heading`; `query_id >
  999 999 999` валидатор молча превращает в null; ложный dirty (клик
  resize-маркера без движения; restoreSnapshot всегда dirty=true);
  отсутствие `beforeunload`-предупреждения; undo во время drag узла
  мерцает старым View (guard `canvas.parentNode === container` в onUp).
- Просмотр: `frameTimes` растёт неограниченно (скользящее окно 20);
  каждый `render()` вешает ещё один mousemove-обработчик на контейнер
  (снимать перед добавлением); анимация «прорисовки ребра» мертва (нет
  CSS-transition по stroke-dashoffset) — добавить transition или удалить
  механизм; облачко «Готово» обрезается сверху для end-узла в верхнем
  ряду (учесть y-54 в bounds()); смена сценария во время проигрывания
  даёт смешанное состояние (resetPlayback в change); узел role="link" без
  обработки Enter/Space.
- Тесты/CI/доки: юнит на нормализацию `icon`; ассерт первых-100 id в
  flood-тесте; восстановление `Setting.login_required` в teardown; гонка
  синтетического DOMContentLoaded в dev/editor.html (флаг booted); пин
  additionals-джобы на тег 4.7.x вместо плавающего main; README
  «Структура» устарела (v0.3.0, нет patch/_settings/counts.json);
  `theme`/`performance` описаны под заголовком «Узел» вместо корня схемы;
  приоритет `query_id` над `url` не задокументирован; dev/scheme.json не
  чистый артефакт генератора (добавить `dev/generate_scheme.rb` или снять
  заявку «генерируется»); кэши bundler/apt в CI — опционально.
