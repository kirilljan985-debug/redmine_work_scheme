# План проекта Redmine Work Scheme

Живой план: текущая задача, правила и состояние. Выполненные задачи
с результатами и проверками — в `PLAN_HISTORY.md`.

## Правило сопровождения изменений

Любое изменение проекта выполняется вместе с актуализацией плана и файла
памяти `AGENTS.md`: до работы фиксируется задача и критерии готовности,
после работы — фактический результат, тесты, коммит, push и состояние CI.
Если изменение не требует отдельного пункта плана, в плане всё равно
записывается краткая отметка о нём.

## Проверка перед завершением задачи

1. Обновить `PLAN.md` и `AGENTS.md`.
2. Выполнить релевантные локальные проверки и тесты.
3. Проверить `git diff` и `git status`.
4. Создать коммит и отправить его в GitHub.
5. Дождаться зелёного CI или зафиксировать диагностику падения в памяти проекта.

## Текущая работа — legacy-поддержка additionals 4.6 + ревью суб-агентами (2026-10-26)

Задача: на живой машине additionals 4.6.0 (легаси-поколение API, требует
Redmine ≥ 7.0 — сверено по клону тега 4.6.0), поэтому блок схемы там не
появляется: поддержано только класс-API 4.7+. Реализовать легаси-ветку по
паттерну redmine_web_window (скилл, раздел 9), затем провести ревью
суб-агентами и зафиксировать результат.

Ключевые факты 4.6.0 (проверены по исходникам): блок — запись в
`DashboardContent#block_definitions` {label:, partial:, max_occurs:};
партиал получает locals `dashboard, settings, block, block_definition,
user`; шестерёнка переключает скрытый div `#{block}-settings` (гейт
`@can_edit`); форма `remote_form_tag _update_layout_setting_dashboard_path
(@project, @dashboard)`; поля `settings[#{block}][key]`; сохранение без
whitelist (`update_block_settings` символизирует ключи) — санитизация на
чтении.

Критерии готовности:

1. `lib/redmine_work_scheme/patches/dashboard_content_patch.rb` (имя =
   константа) добавляет блок work_scheme в block_definitions; модуль
   объявлен безусловно — безопасен под eager-load без additionals.
2. `Scheme.from_settings` — единый источник схемы из настроек (контроллер,
   класс блока 4.7+, legacy-партиал); юнит-тесты (сохранённый JSON / пусто /
   битый → дефолт).
3. init.rb — три ветки: 4.7+ loader.extends; legacy (ignore lib/dashboard_blocks
   + after_initialize include патча); без additionals (ignore). Партиал
   `_block` работает в трёх контекстах (страница / 4.7+ / legacy) с клампом
   width/height из settings; `_settings.html.erb` с полями
   `settings[#{block}][width|height]`; скрытая форма только в legacy под
   `@can_edit`.
4. CI: 4-я джоба legacy-additionals (Redmine 7.0-stable + additionals 4.6.0
   + PostgreSQL + migrate + eager smoke) — легаси-тест регистрации блока
   выполняется только там.
5. Версия 0.5.0; README (4.6+/4.7+); локальные проверки; ревью 3 суб-агентами
   (4.6-интеграция по клону / партиалы и ERB / boot-eager-CI), P0/P1/P2
   исправлены; коммит, push, CI зелёный на 4 джобах; PLAN/AGENTS обновлены.

## Предыдущая работа — оптимизация схемы для слабых устройств (2026-10-26)

Задача: пользователь сообщил, что схема тяжело идёт на слабых устройствах.
Заодно фиксируется точка остановки по additionals: на живой машине стоит
additionals **4.6**, поэтому dashboard-блок там не появится в принципе —
плагин поддерживает только класс-API 4.7+. Переписывание под legacy-4.6
пользователем отменено, остаётся отложенным треком.

Диагноз по коду: backdrop-filter blur(18px) на панелях; анимированные CSS-
фильтры (drop-shadow/brightness) и статические drop-shadow на узлах и
движущемся маркере; каждый кадр проигрывания мутирует главный SVG (маркер,
3 точки хвоста, линия хвоста, поворот) — перерисовывается вся большая
статичная картина; два getPointAtLength за кадр; мусор unshift/slice.

Критерии готовности:

1. Слой-оверлей: маркер/хвост/бейджи/облачко во втором маленьком svg
   (обёртка .ws-canvas), главный статичный SVG не перерисовывается при
   движении маркера; редактор работает как раньше (hit-пути, перепривязка,
   палитра, svgPoint).
2. Кадровый бюджет: предвыборка пути (~64 точки, lerp), поворот раз в 3
   кадра, кольцевой буфер хвоста; в lite — без хвоста, мгновенная отрисовка
   ребра, без chain-flash, ~30 fps.
3. CSS: backdrop-filter убран везде (glass .64→.82), media
   prefers-reduced-transparency удалён; класс .ws-lite отключает SVG-фильтры
   и кейфрейм-анимации, цвета состояний сохраняются.
4. Корневое поле `performance`: auto|high|lite, валидатор (allowlist+passthrough,
   как theme), auto = эвристика (cores/mem ≤ 4 → lite) + адаптив (средний
   кадр > 34 мс → lite на лету); в редакторе селект «Производительность»,
   сериализация, локали ru/en.
5. Версия 0.4.0; README (строка формата + «Слабые устройства»); юнит-тесты
   performance; ruby -c, node --check, YAML, git diff --check; dev-превью
   v=92 (обычный и lite-режим); коммит, push, CI зелёный на 3 джобах.

Результат: всё реализовано (cache-bust в dev дошёл до v=94). Слой-оверлей:
`div.ws-canvas` с основным svg + `svg.ws-overlay-svg` (тот же viewBox,
absolute, pointer-events:none) — маркер/хвост/бейджи/облачко перерисовывают
только маленький слой. Кадровый бюджет: предвыборка пути 65 точек (lerp
вместо getPointAtLength в кадре), поворот раз в 3 кадра и при |Δ|>3°,
кольцевой буфер хвоста, в lite — без хвоста, мгновенное ребро, без
chain-flash, ~30 fps, адаптация в auto при среднем кадре > 34 мс
(noteFrameTime/engageLite). CSS: backdrop-filter удалён везде (glass
.64→.82), prefers-reduced-transparency-блок удалён; анимации фильтров
заменены дешёвыми (decision-wait → ws-pulse, completion-flash → opacity);
`.ws-lite` отключает фильтры/анимации/хвост. Поле `performance`
(auto|high|lite) в валидаторе, рендерере, редакторе (селект + сериализация +
restoreSnapshot) и локалях. Браузерно проверено: полный прогон «Готово
10/10», lite без trail и без анимаций, hit-пути редактора кликабельны
(elementFromPoint pass), бейджи 2/2 в overlay, оверлей выровнен при зуме.

Грабли, пойманные смоук-тестом (исправлены на месте):
1. Guard гонки счётчиков `self.svg.parentNode !== self.container` лёг от
   переноса svg в canvas — заменён на `self.canvas.parentNode`.
2. `.ws-edge-hit` унаследовал pointer-events:none от overlay-svg — добавлен
   явный `pointer-events: stroke`.
3. lite считался только в конструкторе — селект редактора не применялся до
   пересоздания View; вынесено в `applyPerformanceMode()`, зовётся из render().

Итог: коммит `b472ed8`, CI зелёный на трёх джобах (run 40346829096).
