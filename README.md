# Redmine Work Scheme

Плагин Redmine: **интерактивная схема процесса** на главной странице.

- SVG-схема рисуется прямо в браузере (vanilla JS, **без внешних CDN** — работает
  в закрытом контуре);
- подсказки при наведении на узел (описание этапа, ответственный отдел);
- клик по узлу открывает **страницу этапа** с полным описанием (или любую
  внешнюю страницу, если она задана);
- **проигрывание сценариев**: движение «ТЗ» по схеме, включая сценарий
  «возврат на доработку» с циклом;
- **живые счётчики** — число задач на этапе (опционально, см. ниже; если
  трекеры/запросы ещё не заведены — просто не показываются, без ошибок);
- редактирование схемы — визуальным редактором (`/work_scheme/edit`, только
  администратор) или JSON в настройках плагина, без правки кода.

## Установка

```bash
cd /путь/к/redmine/plugins
git clone https://github.com/kirilljan985-debug/redmine_work_scheme.git redmine_work_scheme
```

Перезапустить Redmine. Миграций БД нет, gem-зависимостей нет.

**Совместимость:** Redmine 6.0+, Ruby 3.2+. Необязательная интеграция с
плагином [Additionals](https://www.alphanodes.com/additionals) (блок на
дашборде) требует additionals 4.7+; без него плагин работает автономно.

Проверка: «Администрирование → Plugins» — там появится «Work Scheme»;
страница схемы — по адресу `/work_scheme`.

## Как редактировать схему

Два способа:

1. **Визуальный редактор** (рекомендуется) — страница `/work_scheme/edit`,
   доступна только администратору. Подробно — в разделе «Редактор схемы» ниже.
2. **JSON в настройках** — Администрирование → Plugins → Work Scheme →
   «Настроить», поле **JSON схемы**.

Структура:

```json
{
  "title": "Схема",
  "theme": "classic",
  "nodes":  [ ...узлы... ],
  "edges":  [ ...связи между узлами... ],
  "scenarios": [ ...сценарии проигрывания... ]
}
```

### Узел (nodes)

`theme` — визуальная тема схемы: `classic`, `ocean`, `graphite`, `warm` или
`paper`. Тема задаёт фон полотна и оформление редактора.

| Поле | Тип | Обяз. | Описание |
|------|-----|-------|----------|
| `id` | строка | да | Латиница/цифры/`-`/`_`, уникальный |
| `title` | строка | да | Надпись на узле |
| `type` | строка | нет | `start`, `process` (по умолчанию), `decision` (ромб), `end` |
| `dept` | строка | нет | Ответственный отдел (в подсказке) |
| `description` | строка | нет | **Короткий текст подсказки при наведении** |
| `page` | строка | нет | **Полное описание этапа** (wiki-разметка) — страница `/work_scheme/stages/<id>`, открывается кликом по узлу |
| `url` | строка | нет | Вместо `page`: адрес для перехода по клику — `http(s)://…` или от корня сайта (`/projects/…/wiki/…`); прочие схемы (`javascript:` и т.п.) валидатор отклоняет |
| `icon` | строка | нет | Встроенная иконка: `user`, `document`, `search`, `decision`, `certificate`, `gear`, `rocket`; назначается в редакторе перетаскиванием |
| `query_id` | число | нет | ID сохранённого запроса Redmine для **живого счётчика** (см. ниже) |
| `x`, `y` | числа | нет | Координаты левого верхнего угла (по умолчанию 0) |
| `w`, `h` | числа | нет | Размер (по умолчанию 140×56) |
| `font_size`, `font_weight`, `font_family`, `text_color` | число/строка | нет | Стиль заголовка блока на схеме; размер 8–32, семейство `sans-serif`/`serif`/`monospace` |

### Связь (edges)

| Поле | Тип | Описание |
|------|-----|----------|
| `from`, `to` | id узлов | Стрелка из узла в узел |
| `label` | строка | Подпись на стрелке («да», «нет — на доработку») |
| `label_font_size`, `label_font_weight`, `label_font_family`, `label_text_color` | число/строка | Стиль подписи стрелки |
| `color` | строка | Необязательный цвет стрелки в формате `#RRGGBB` |
| `dashed` | true/false | Пунктирная стрелка |
| `route` | `straight`/`arc`/`elbow`/`u` | Прямая, дуга поверх схемы, Г-образное колено или П-образный обход |
| `bend` | число 0–200 | Изгиб для `arc`/`elbow`/`u` (по умолчанию 50) |
| `from_side` | `left`/`right`/`top`/`bottom` или пусто | Сторона узла, из которой стрелка выходит (пусто — автоматически) |
| `to_side` | `left`/`right`/`top`/`bottom` или пусто | Сторона узла, в которую стрелка входит (пусто — автоматически) |

## Редактор схемы (`/work_scheme/edit`, только администратор)

Полноценный визуальный редактор, интерфейс на русском:

- **Палитра «Готовые элементы»** — новые узлы, стрелки и иконки добавляются
  перетаскиванием на холст: блок бросается на свободное место, стрелка —
  на исходный узел, затем выбирается целевой.
- **Клик по узлу** — панель свойств: заголовок, тип (Старт/Процесс/Решение/
  Финиш), отдел, описание подсказки, текст страницы этапа (wiki), ссылка,
  ID запроса (`query_id`), координаты/размер (восемь маркеров размера),
  стиль текста блока; удаление и дублирование.
- **Клик по стрелке** — панель стрелки: привязка «Откуда»/«Куда» (любой блок),
  подпись, форма (Линия/Дуга/Колено/П-образная), стороны выхода/входа,
  пунктир, изгиб, цвет, стиль подписи, «Развернуть направление», удаление.
- **Перетаскивание концов стрелки** — у выбранной стрелки оранжевые точки на
  концах: тяните конец на другой блок — стрелка перепривязывается (цель
  подсвечивается зелёным). Тянете точку-начало — меняется исходный блок.
- **Перетаскивание узлов** мышкой по холсту.
- **История и выравнивание** — Undo/Redo (Ctrl+Z/Ctrl+Y), множественное
  выделение через Shift+клик, выровнять/распределить по X/Y, проверка
  пересечений блоков.
- **Тема интерфейса** — пять тем (Redmine Classic, Ocean Blue, Graphite Dark,
  Warm Office, Paper Canvas), сохраняется в поле `theme` схемы.
- **Сценарии** — названия и шаги (id узлов через запятую), режим «Кликом»:
  кликайте блоки в порядке маршрута, включая повторные проходы.
- **«Сохранить схему»** — серверная валидация и запись в настройки плагина;
  при ошибках они показываются в статусе, настройки не меняются.
  **«Скачать JSON»** — резервная копия текущего состояния редактора.

## Где что на схеме

- Страница схемы: `/work_scheme` (то же содержимое после встраивания в дашборд
  появится блоком; страница остаётся как прямая ссылка).
- Страница этапа: `/work_scheme/stages/<id узла>` — генерируется из поля
  `page` узла (wiki-разметка).

### Сценарий (scenarios)

| Поле | Описание |
|------|----------|
| `id`, `title` | Идентификатор и название («Успешное прохождение», «Возврат на доработку») |
| `steps` | Последовательность id узлов, которую «проходит» ТЗ при проигрывании |

Ошибки валидации показываются прямо в настройках и на странице схемы —
опечатка в JSON не сломает Redmine.

## Живые счётчики

Счётчик узла = число задач в сохранённом запросе Redmine:

1. Создайте сохранённый запрос (например, «ТЗ на анализе»: трекер «ТЗ»,
   статус нужной стадии), откройте его и посмотрите ID в адресной строке
   (`/issues/123?...` — число после `/issues/`).
2. Впишите это число в узел схемы: `"query_id": 123`.
3. У узла с `query_id` рисуется бейдж с числом задач (правый верхний угол
   блока); клик по такому узлу открывает отфильтрованный список задач
   (`/issues?query_id=123`).
4. Счётчики запрашиваются одним GET-запросом `/work_scheme/counts?ids=1,2,3`
   и учитывают права Redmine: считаются только сохранённые запросы, видимые
   текущему пользователю. Если запрос удалён, не существует или недоступен —
   узел просто показывается **без счётчика**, без ошибок.

## Тесты

```
bundle exec rake redmine:plugins:test NAME=redmine_work_scheme RAILS_ENV=test
```

CI: GitHub Actions гоняет тесты на Redmine `7.0-stable` и `master` при каждом push,
плюс отдельная джоба с установленным additionals (PostgreSQL) — она проверяет
ветку подключения dashboard-блока. На каждой джобе выполняется smoke-проверка
eager-загрузки, как в production. При падении хвост тестового лога выводится
в аннотации прогона.

## Разработка и dev-превью (без Redmine)

```
python -m http.server 8123        # запустить из папки плагина
```

- `http://127.0.0.1:8123/dev/preview.html` — схема: рендер, подсказки,
  проигрывание сценариев (данные — `dev/scheme.json`, генерируется из схемы
  по умолчанию).
- `http://127.0.0.1:8123/dev/editor.html` — редактор (кнопка «Сохранить схему»
  в превью не работает — некуда отправлять; на живом Redmine работает).

Локальные проверки без Redmine: `ruby -c` (.rb), `node --check` (.js),
`erb -x -T- файл.erb | ruby -c`, чистый minitest по валидатору. Полный прогон —
только CI (Linux).

```

app/views/work_scheme/edit.html.erb        страница редактора
app/views/settings/_work_scheme.html.erb   JSON в настройках плагина
assets/javascripts/work_scheme.js          SVG-рендерер (холст, подсказки, проигрывание)
assets/javascripts/work_scheme_editor.js   визуальный редактор
assets/stylesheets/work_scheme.css         стили
config/locales/en.yml, ru.yml              локализация
test/unit, test/integration                тесты (minitest, в окружении Redmine)
.github/workflows/test.yml                 CI (Redmine 7.0-stable, master, + additionals)
dev/preview.html, dev/editor.html          dev-превью без Redmine
AGENTS.md                                  память проекта: правила, грабли, статус
PLAN.md                                    живой план задач с критериями готовности
```
